# Планирование сбора

Collect сначала делает чистый базовый интервал, затем запускает внешние/native сборщики и продолжает периодические снимки. System/GPU inventory дополняется при сборке отчёта. Main sampling и очередь инструментов имеют разные роли; двухфазность не устраняет observer effect во время трассировки.

По умолчанию max-workers=2. Если focus допускает память, oomkill первым занимает слот; остальные идут через оставшиеся слоты. Все используют общий дедлайн: базовый интервал + длительность + до 5 s запаса. Завершение процесса может добавить время на cleanup. Гарантии полного окна каждому queued-инструменту нет.

Увеличение duration удлиняет и первые трассировки, поэтому само по себе не исправляет очередь deep. Max-tool-seconds позволяет ограничить одну команду, но укороченные результаты могут остаться partial. Рост workers увеличивает параллельную компиляцию BCC и риск влияния на VM. Пакетного планировщика с отдельным полным окном на каждый инструмент пока нет.

SIGINT/SIGTERM сохраняет доступный частичный отчёт; повторный сигнал завершает процесс немедленно. Для --self-profile/--pprof записывается cProfile/pstats, не HTTP-профиль.

```bash
python3 linuxperf.py collect --profile deep --max-workers 2 --self-profile linuxperf.pstats -o deep.json
```

Реализация: [linuxperf.py](../../linuxperf.py) — `collect`, `run_tools`, `tool_duration`, `handle_signal`.
